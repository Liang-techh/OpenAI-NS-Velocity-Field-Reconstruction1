# Finite-N density adapter identity guard — 2026-10-29

Goal ACTIVE / INCOMPLETE. Static review found a source-namespace defect in the existing ordinary-Z finite-N density kernel: `coerce_ordinary_jet` could relabel an already explicit graph adapter, and `_common_operations` chose the first adapter before `_normalize` relabeled the rest. This could bypass the existing ordinary-jet binary-operation identity check and silently mix source graphs in signed m15 density or endpoint inputs. It was a possible code path, not evidence that an accepted result was actually corrupted.

The updated `src/openai_ns_reconstruction/original_finite_N_density_kernel.py` rejects incompatible explicit adapters by object identity, including a conflicting explicitly requested adapter. The singleton `PYTHON_OPERATIONS` is explicit and is not interchangeable with a graph adapter. An unbound ordinary jet can inherit the unique adapter while preserving its rows; a bare numeric literal is separately marked and converted by that adapter's `constant` callback, including its zero derivative rows. An opaque unbound source scalar is not interpreted as a numeric literal. Callers using an integer as an opaque source handle must wrap it as an explicit ordinary jet or supply its actual source object; a bare number is treated as a numeric literal. Existing clients that created distinct adapter instances for one source now need to share the same adapter object. This guard prevents one accidental namespace merge; it does not prove that a caller's unbound or same-adapter inputs have the same physical source.

A new frozen guard fixture was entered once without calling density, endpoint, correlation, binary arithmetic, graph traversal, or an ancestor calculation. It passed 27 of 28 checks. The failure exposed a separate behavior: explicit numeric values were not passed through the adapter's `constant` callback, although derivative zero rows were. The complete failed fixture, source bytes and receipt are preserved in `current_finite_n_adapter_guard_failure.json`; it was not reentered.

The repair lifts explicit numeric values and zero rows through the callback while preserving an explicitly supplied opaque source scalar. A second independently frozen, distinct fixture was entered once and passed both checks for those two cases. It did not rerun the first fixture or any source-density computation. The first fixture's 27 passing checks describe its frozen version, not a rerun of the final file; the second fixture checks only the changed literal-lift path. There is no complete integration or physical-source validation in this turn. Both reports embed their exact source, checkpoint, entry and result; the older source before this change remains available in the parent commit.
